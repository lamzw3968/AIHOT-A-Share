# MyHOT 财经 V1

当前行业配置面向中国 A 股 / 财经资讯、事件、热点和报告。保留 MyHOT 站名、`myhot` MCP 前缀与接口字段；不建设行情数据库、证券主数据、交易或目标价功能。

## 行业配置

| 分类 | 内容类型 | 边界 |
|---|---|---|
| market 市场 | market_move | 指数、板块股价、成交额、资金流 |
| company 公司 | company_event | 经营、业绩、订单、合同、商业化 |
| industry 行业 | industry_event | 供需、产能、产品价格、产业链 |
| policy 政策 | policy_event | 正式政策、监管及交易规则 |
| capital 资本 | capital_event | IPO、融资、并购、控制权、股权、回购增减持 |
| macro 宏观 | macro_event | 宏观数据、经济变化、海外宏观传导 |

无新增事件的评论为 `opinion_analysis`，分类按研究对象选择。分类 key 是公开身份，投入生产后保持稳定。资本交易优先资本、正式政策优先政策、公司业绩归公司；产业价格与板块股价分别归行业与市场。

预筛宽召回：资本市场、公司、产业链、监管、宏观有实质关联即 PASS，明确无关才 BLOCK，材料不足为 UNKNOWN。不因缺股票代码、缺“A股”字样或主体未上市而 BLOCK，也不编造海外新闻与中国市场的联系。

两次独立评分仍为 0–100；六种事实类型权重 `3/1/2/4/0`，观点 `1/3/1/4/1`，维度顺序为影响、增量、证据、范围、研究可用性。门槛 `60/65/76`，理解门槛 50，尚未财经校准。广告、推广、重复无增量、情绪观点和模板行情压低；摘要忠实保留金额、币种、百分比、报告期及阶段，不生成买卖建议、目标价或确定涨跌预测。

同公告转述为 SAME_OCCURRENCE，同交易不同阶段为 SAME_STORY；不同公司、报告期、交易日或订单为 UNRELATED，多事件盘点为 ROUNDUP。七机构白名单用于主体标签及身份守卫；未知公司保留在标题、摘要及 `fact.subject`，不强塞机构 `subjects`。

## 主题与信源

最初 41 个财经主题均以 `finance-` 开头。2026-10-08 题材榜扩展增加 10 个细分主题，当前为 51 个：7 个机构、34 个关注主题、10 个资讯类型。主题目录只显示当前行业配置，按配置顺序排列；旧主题数据、详情 URL、计数和 sitemap 保留，旧 slug 不换含义。新增讨论候选不写进此目录，详见[题材热点榜 V1](topic-hot-v1.md)。

`industry/sources.json` 的 `sources` 为空。新空环境需要通过后台另行配置信源；重复 seed 不覆盖既有来源，也不自动暂停旧 AI 来源。V1 沿用现有财经来源，不新增来源或依赖 Jina，信源全文权限仍由来源授权决定。

模型榜和 Codex 重置监控通过 Feature 关闭，通用模块保留。报头为“A股日报／周报／月报”。条款与隐私页仍需运营者在上线前确认。

## 兼容行为

- API、RSS、Web、MCP 共用 publication 读取层；六分类使用同一词表，删除旧 `tip/opinion` 合并特例。
- 不在当前词表的历史分类，网站摘要和 selected snapshot/changes 输出为 `null`；不修改原数据库分类、账本 JSON、回执、序号、游标或发布时点。
- 主题目录过滤不影响详情和 sitemap，不绕过未来发布时点、缓存截止或 ETag。
- 初始财经 V1 不新增 API 路径、字段或数据库迁移。2026-10-08 题材榜扩展只新增网站自用接口和独立衍生快照表，原 v1/机器协议保持不变。OpenAPI 继续动态读取行业分类。

## 本地验收与后续工作

依赖用 `npm ci`；测试使用独立本地 PostgreSQL 17，库名以 `_test` 或 `_ci` 结尾，迁移前核对本地地址及空库。先 typecheck，再串行后端测试、Web build/tests、本地 smoke、差异与凭据检查。真实外部服务关闭；仅隔离测试进程使用虚假凭据与 loopback 假 Provider，保留预算/回执验证。

关闭回归测试在 POSIX 发送真实 SIGTERM；Windows 的 Node 子进程信号会强制终止进程，因此测试用 IPC 进入同一 SIGTERM 处理函数，保留提交、回执、发布和恢复断言。Windows 验收不证明 POSIX 信号交付。该平台适配仅在测试代码中，不修改应用关闭逻辑。

完整备份恢复测试需要 PostgreSQL 17 的 `pg_dump` / `pg_restore` 在 PATH 中。Windows 测试使用系统 tar 与 .NET Framework C# 编译器生成临时转发程序，适配空归档与失败计数；POSIX 仍使用原 sh fixture。归档、恢复、重试与保留数量的断言没有删减，生产备份实现未改。

评测缓存回归逐项比较评分、覆盖率、用量等结果；真实耗时可能因缓存命中而变化，另断言其为非负整数且不超过子进程实际寿命，不要求两次耗时相同。完整后端验收从空库迁移开始；不要把已经留下队列与事件数据的诊断库作为空库复用。

本机 Docker Engine 不可用，因此使用独立的便携 PostgreSQL 17.11 在 loopback 上验收，未验证 Docker 镜像构建或容器部署。测试库、日志和临时工具均在忽略的 `.data/finance-validation/`，不进入提交。
